## 怎么跑

1. 把 `sealdice-core.exe` 放到一个**固定目录**里（不要放在临时目录，程序会拒绝启动）
2. 双击运行，或命令行执行：

   ```powershell
   .\sealdice-core.exe
   ```

3. 浏览器打开 `http://127.0.0.1:3211` 进管理界面

首次启动会在 **exe 同级目录**自动创建 `data\`，所有数据都在里面：

```
你的目录\
  sealdice-core.exe
  data\                 ← 数据库、serve.yaml、日志、extra 全在这里
```

**备份就是备份整个 `data\` 目录。**

> ⚠️ 不要放在 `%TEMP%` 之类的临时目录，程序会检测到并拒绝运行（官方保护机制）。

## 身份绑定怎么用

### 前提：打开总开关

管理界面 → **杂项设置 → 身份绑定 → 启用身份与日志绑定**（默认是关的）。

### 玩家侧

| 指令 | 说明 |
|---|---|
| `.bind <旧QQ号>` | 绑定个人身份 |
| `.bind status` / `.bind cancel` | 查看 / 取消 |
| `.unbind` | 解除个人绑定 |
| `.group bind <旧群号>` | 群绑定（需管理权限），让两边日志共用一份 |
| `.group status` / `.group unbind` | 查看 / 解除群绑定 |
| `.bind doctor` / `.group doctor` | **自检所有绑定**，出问题先看这个 |

### 验证码走哪条通道

**不需要额外开关，系统自动判断：**

| 通道 | 可用条件 |
|---|---|
| 私聊 | 民间 bot（OneBot 连接）在线且启用 |
| 邮箱 | 「邮箱通知」配齐了（发件邮箱 / 邮箱密钥 / SMTP 地址） |

两条都可用时，按「**优先用邮箱发送**」这个选项决定先后：

* **关闭（默认）** → 先试私聊，发不出去才走邮箱
* **开启** → 先寄邮箱，邮箱不可用再退回私聊

两条都不通时，会在回复里说明具体缺什么，并等条件满足后自动重试。

**确认方式**：

* 私聊码 → 用旧 QQ 号打开与**民间 bot** 的私聊，把码回复过去
* 邮箱码 → 收到邮件后，在**官方 bot** 这边回复验证码

**群绑定只有私聊通道**（群号推不出邮箱，而且要证明的是"这个群"），
验证码私聊发给**旧群的邀请人**（把骰子拉进旧群的那个人）。

## 邮箱通道怎么配

### 1. 开 SMTP

管理界面 → **杂项设置 → 邮箱通知**：

| 项 | QQ 邮箱填什么 |
|---|---|
| 邮箱通知 | 开启 |
| 发件邮箱 | `你的QQ号@qq.com` |
| 邮箱密钥 | QQ 邮箱的**授权码**（不是登录密码；在 QQ 邮箱设置→账户里生成） |
| SMTP 地址 | `smtp.qq.com` |

> **端口**：不写就用默认的 465(SSL)。想指定可以写成 `smtp.qq.com:465` 或 `:587`。
> 465 走隐式 SSL，其它端口交给 gomail 自动 STARTTLS。
>
> **不要用 25**：阿里云/腾讯云等普遍封锁 25 端口，会得到
> `dial tcp <ip>:25: i/o timeout`。这正是旧版本发不出邮件的原因。

### 2. 不需要再开别的开关

邮箱通道**没有独立开关**：只要上面三项配齐了，验证码就能走邮箱。
想改变优先级就去 **杂项设置 → 身份绑定 → 优先用邮箱发送**。

### 3. 先用「发送测试邮件」验证

邮箱通知那块有个 **发送** 按钮。**建议先测通**——不然玩家的绑定会卡在投递失败。
（页面下方会实时显示邮箱通知是否已配齐。）

## 配置项速查（`data\<名字>\serve.yaml`）

| 键 | 默认 | 说明 |
|---|---|---|
| `identityBindEnable` | `false` | 绑定功能总开关 |
| `identityBindUseVerificationCode` | `true` | 验证码开关（关掉 = 放弃防抢号） |
| `identityBindUseEmailCode` | `false` | 邮箱通道；**需要先配好 SMTP** |
| `identityBindCodeLength` | `6` | 4~8 |
| `identityBindCodeExpireSec` | `600` | 60~3600 秒 |
| `identityBindCooldownSec` | `60` | 两次发起绑定的最小间隔 |
| `logMultiBotDedupWindowSec` | `5` | 同群多 bot 时的日志去重窗口，5 = 原版行为 |
| `officialQQRequestTimeoutSec` | `60` | 官方 QQ 请求超时 |
| `officialQQChunkedUploadEnable` | `false` | 分片上传（可保留文件名） |
| `mailSmtp` | — | 支持 `host` 或 `host:port` |

新增的键官方主线读不懂时会**静默忽略**，所以不影响将来换回官方版本。

## 已知限制

* 日志跨群读取要求旧群对象在内存里（骰子进过那个群）。`.group doctor` 能查出来。
* **两个独立的海豹实例**各跑一个 bot **不支持**——两种连接必须挂在同一个实例上。
* 群配置（前缀、自动回复、牌堆）**不共享**，只有日志和玩家数据共通。
* 两边都有日志时，绑群后只看得到归一后（旧群）那一份；官方群自己那份**不会被删**，
  解绑或换回官方主线后就又能看到。

## 换回官方主线

数据可以直接沿用（没有改数据库结构），换 exe 即可。注意一点：

**回退后哪些数据还能看到，取决于你绑了几个维度。**

| 个人绑定 | 群绑定 | 回退后 |
|---|---|---|
| ✅ | ✅ | 完全正常 |
| ✅ | ❌ | 官方群里的属性改动会读不到 |
| ❌ | ✅ | 玩家属性读不到 |
| ❌ | ❌ | 正常（没参与绑定） |

建议：**两个维度都绑**。详见仓库 `docs/how-to-revert-to-upstream.md`。
