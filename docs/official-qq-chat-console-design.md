# 官方 QQ 聊天控制台 · 设计稿

> 状态：**待评审**（尚未写代码）
> 目标：在 WebUI 里提供一个类似桌面版 QQ 的聊天界面，让骰主直接查看并操作**官方 QQ 机器人**这侧的消息；民间 bot 侧不做（骰主可以直接上号看）。

---

## 一、目标与非目标

**目标**

1. 会话列表：官方 bot 参与过的**群**与**私聊**，显示群名/昵称、最后一条消息、未读数。
2. 消息流：单个会话的历史消息（收到的 + 骰子发出的 + 骰主从控制台发出的），支持文字与图片/文件的展示。
3. 发送：以机器人身份往该会话发文字（可 @ 某人）。
4. 实时：新消息自动出现，无需手动刷新。
5. 可见性：三种来源在界面上明确区分（群成员/私聊用户 · 骰子自动回复 · 骰主控制台发送）。

**非目标（本期不做）**

- 不镜像官方群的**全量聊天**（平台限制，见下）。
- 不做民间 bot（OneBot）侧的聊天界面。
- 不做图片/文件**发送**（第二阶段再说；接收侧的展示要做）。
- 不做消息撤回/删除、不做已读回执。
- 不改数据库结构（见"四、存储"）。

---

## 二、平台约束（决定能力上限）

| 约束 | 影响 |
|---|---|
| **群主在官方群设置里授权后，群内全部消息都会推给 bot** | 群会话能看到**完整消息流**；未授权的群只能看到 @ 消息，UI 按群显示权限状态 |
| 官方**群**主动消息：群主授权后完全放开；官方**私聊**主动消息仍有额度 | 群会话发送不受额度限制；**私聊发送仍可能因额度失败**，必须如实显示错误 |
| 历史消息**无法回溯** | 只能从功能启用后开始记录 |
| 群信息 `GET /v2/groups/{group_openid}/info`，**30 QPM** | 只在会话首次出现 / 手动刷新 / 打开会话时查，并缓存（含 `group_name`、`group_member_num` 等） |
| 官方媒体 URL 有有效期 | 展示时若已过期显示占位；可选"下载到本地"（默认关闭，占磁盘） |

## 三、会话标识与采集点

**会话键（`conversationKey`）**

```
group:<group_openid>        # 官方群
c2c:<user_openid>           # 官方私聊
```

与现有 `OpenQQ-Group:<uin>-<openid>` / `OpenQQ:<uin>-<openid>` 的**平台 ID 不同**：控制台只关心官方侧 ID，不参与身份绑定归一（避免把绑定逻辑卷进来）。

**采集点（两处，都在官方适配器内）**

1. **收到**：`platform_adapter_official_qq.go` 解析完消息、交给 `Execute` 之前 → 记录（原始文本、图片/文件 URL、发送者昵称、官方 `msg_id`、时间）。
2. **发出**：适配器实际发送成功之后 → 记录（区分 `bot` 自动回复 / `console` 骰主发送）。

去重：以官方 `msg_id` 为唯一键（同一 `msg_id` 只落一条）。

**不记录**：入站被拦截的消息、非官方端点的消息、群里的非 @ 消息（平台不推送）。

## 四、存储（**不改数据库**）

```
data/chat-console/
    index.json                    # 会话元信息：群名/昵称/成员数/**权限状态**/最后消息时间/未读
    group_<group_openid>/         # 按天分文件，便于滚动清理与分页
        2026-11-05.jsonl
    c2c_<user_openid>/
        2026-11-05.jsonl
```

一条消息记录：

```json
{
  "id": "官方 msg_id 或 发送流水号",
  "ts": 1761600000,
  "dir": "in|out",
  "source": "user|bot|console",
  "sender_id": "OpenQQ:...",
  "sender_name": "许烁",
  "text": "原文（含 CQ 码）",
  "media": [{"kind": "image|file", "url": "...", "name": "..."}],
  "msg_id": "官方 msg_id"
}
```

**保留策略**（按"全部群消息"的量级定）：**按天滚动，默认保留 30 天**；单会话最多 5000 条；媒体只存**元信息**（URL + 文件名/大小），不落原始图片/文件（URL 过期后显示"已过期"）。清理按天删最旧的日文件（原子写：临时文件 + rename）。

**为什么不用数据库**：与既有准则一致——新增功能不得改变 schema，回退旧版本时 `data/chat-console/` 整个目录被忽略即可，零风险。

**回退安全性**：旧版本不认识该目录，也不会读写；删除该目录等于清空控制台历史。

## 五、后端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/chat-console/conversations` | 会话列表（分页、按最后消息时间倒序）；含未读数 |
| GET | `/api/chat-console/messages?key=...&before=<ts>&limit=50` | 历史分页（向前翻） |
| POST | `/api/chat-console/send` | `{key, text, at?: [user_openid]}` → 以机器人身份发送；返回官方错误（额度/权限/频率） |
| POST | `/api/chat-console/refresh-info` | 重新拉群信息（`/v2/groups/{id}/info`），受 30 QPM 限制，做本地节流 |
| POST | `/api/chat-console/read` | 标记已读（清未读） |
| GET | `/api/chat-console/stream` | **WebSocket**：推送 `message` / `conversation` / `error` 事件 |

所有接口要求 WebUI 登录态（复用现有鉴权，不新做一套）；WebSocket 在握手时校验同一会话。

## 六、前端页面

```
┌ 左侧一级入口「聊天」 ────────────────────────────────────────────┐
│ 会话列表（群 🏠 / 私聊 👤 图标区分，未读小圆点）  │  消息流 + 输入框  │
│  读书分享会(256)  许烁: 骰个侦查…                │  [许烁] 骰个侦查   │
│  许烁(私聊)       [骰子] 侦查 45/60 成功          │  [骰子] …          │
│  …                                              │  [我] 嗯            │
│                                                 │  ─────────────     │
│                                                 │  [输入框] [发送]    │
└─────────────────────────────────────────────────┴────────────────────┘
```

- 消息气泡：群成员/私聊用户（左）· 骰子自动回复（左，浅色标签"骰子"）· 骰主控制台发送（右，"我"）
- 群会话顶部按群显示权限状态：**已授权**（能看到全部群消息）/ **仅 @ 消息**（群主还没在官方群设置里开"允许 bot 获取群消息"）
- 发送失败：气泡下方红色错误（额度不足 / 无权限 / 频率超限），保留原文可重发
- 图片点击放大；文件显示名 + 大小（URL 过期时显示"已过期"）

## 七、安全与一致性

- **权限**：仅 WebUI 登录的骰主可用；不提供匿名/只读令牌（本期）。
- **敏感词**：控制台发送属**骰主本人操作**，默认**不走过站拦截/打码**；但要记录日志（谁在什么时候发了什么），便于事后追查。
- **与既有功能的关系**：不参与身份绑定归一、不写 `censor_log`、不影响日志（storylog）；与"数据共通/日志共通"互相独立。
- **频率**：控制台发送做本地节流（同一会话 1 条/秒），避免触发官方 429。

## 八、实施步骤

1. `dice/official_qq_chat_console.go`：存储（jsonl 读写 + 滚动清理）、会话索引、采集钩子。
2. 适配器挂接：收/发两个采集点（`platform_adapter_official_qq.go`）。
3. `api/chat_console.go`：REST + WebSocket。
4. `chaye2333/sealdice-ui`：新增页面与入口、消息气泡组件、发送与错误呈现、WS 接入。
5. `Dockerfile` 的 `UI_REF` 更新 + CI 烟雾测试加 needle（页面标题字符串）。
6. 文档：`docs/official-qq-chat-console.md`（含"只有 @ 消息"等限制）+ README 功能表；回退手册补一句"新增 `data/chat-console/` 目录，删掉即可"。

## 九、测试计划

- 单测：消息落盘/读回、滚动清理（500 条/200MB 边界）、`msg_id` 去重、会话索引更新、未读计数。
- 单测：发送时的错误映射（额度/权限/频率 → 中文提示）。
- 集成（假腾讯 API）：收消息 → 落盘 → WS 推送 → 前端可选；发送 → 记录 `out/console`。
- 回退验证：删除 `data/chat-console/` 后主程序行为不变；旧版本镜像启动不受影响。

## 十、待核对（开工前确认）

1. botgo 是否已有 `GroupInfo` 的便捷封装（`/v2/groups/{id}/info`）。
2. 官方 C2C 消息里是否带用户昵称字段（决定私聊列表显示什么）；没有就用 openid 尾号 + 可手填备注。
3. WebUI 现有 WebSocket 基础设施能否复用（`api/` 里是否已有 ws 端点）。
4. **如何判断某群"已授权群消息"**：官方接口若有权限字段就直接读；若没有，就用"是否收到过非 @ 消息"推断，并在 UI 上标注为推断值。
5. 官方**主动私聊**当前的实际额度/QPM（群已放开，私聊尚未确认）。
