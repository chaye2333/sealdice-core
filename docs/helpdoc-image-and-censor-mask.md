# 出站敏感词打码 & 帮助文档图片化

面向**公益骰子**：用户可能故意往群里投敏感词，而海豹原来的策略是「检测 → 拦截提醒 →
拉黑警告」——但它管不住**骰子自己的输出**（掷骰结果、自定义回复、帮助文档）把敏感词
带到平台上。这两个功能就是补这一块。

> 两个功能都**只写配置与文件，不动数据库**（沿用 `data/censor/*` 词表文件与
> `data/helpdoc/help_config.yaml`），所以随时可以换回旧版本，见第三节。

---

## 一、出站敏感词打码（口口）

**位置**：管理界面 → 拦截词 → 「出站掩码」。

**行为**：骰子**要发出的文本**命中敏感词时，把命中的词替换成**等长掩码**：
4 字词 → `口口口口`，2 字词 → `口口`。掩码字符可改（默认 `口`，最多 4 个字符）。
不再把整条消息换成「完全拦截」的文案（那是关闭掩码时的行为）。

**计数规则（容易被忽略，务必知道）**：

| 出站来源 | 是否打码 | 是否计违规 | 说明 |
|---|---|---|---|
| 帮助文档（`.help <ID>` / `.help <关键词>` / `.find`） | 是 | **否** | 帮助文档是骰主主动公开的内容；计数会把骰主自己拉黑 |
| 其它（掷骰结果、自定义回复、合并转发、私聊回复） | 是 | **是** | 打码**的同时**照常计数并按各等级阈值警告 / 拉黑，风控强度与关闭掩码时一致 |

掩码走的是**纯匹配**路径：直接问敏感词引擎，不写命中记录、不计数、不碰怒气值；
「其它出站」是先按原逻辑记账（`CensorMsg`），再打码发出。

**CQ 码与海豹码内部不会被替换**：`[CQ:image,file=...]`、`[img:...]` 这类结构会整段跳过，
否则改坏一个参数轻则图片/文件发不出去，重则把码截断成乱文本。

配置键（`serve.yaml`）：

```yaml
censorMaskEnable: true     # 默认 false
censorMaskChar: "口"       # 默认「口」
```

**不足 / 风险**：

1. 只是**子串匹配**：谐音、拆字、繁体、emoji 间隔、英文同义词都能绕过；
   反过来也可能误伤（"天主教" 里含 "天主" 这类词表设计问题要自己调）。
2. 掩码会让句子读不通，而且等于告诉所有人「这里被屏蔽了」。
3. 只救**骰子的输出**。用户自己发进来的敏感词平台早就看到了。
4. 出站口必须**逐个覆盖**：目前覆盖了群回复、私聊回复、合并转发、帮助文档四类；
   以后新增发送通道（定时消息、扩展直接调用适配器）需要补上。
5. 引擎对**同一位置重叠的多个词只报一个**（"天主教" 只报 "天主"），所以可能只打掉一部分。
6. 命中来自**拼音匹配 / 过滤字符正则**时，词表里的原词可能并不字面出现在文本里，
   这种命中不会打码（但仍然计数）。

> 顺带建议：拦截词页面里的「发送编码后的命中详情」（`SendEncodedDetails`）是把命中原文
> **base64** 后发到会话里。base64 不是加密，等于把原文又发了一遍，建议默认关掉。

## 二、帮助文档图片化

**位置**：管理界面 → 帮助文档 → 图片渲染。

**触发条件**（二选一，二者都要求总开关打开）：

- 正文**命中敏感词**；或
- 正文**字符数 ≥ `imageRenderMinLength`**（按 rune 计，中文一字算一个；0 = 关闭按长度触发）。

命中敏感词时，图片里**默认保留原文**（转图片的目的就是让内容送达）；
勾选「图片里也打码」后，图片里同样是 `口口`。

**出口**：`.help <ID>`、`.help <关键词>`、`.find` 三处帮助正文。掷骰结果与其它回复不受影响。

**一次性、不缓存**：每次请求都由渲染后端**现场出图**，再以 `[CQ:image,file=base64://...]`
内联发送——图片不会落在任何可被复用的 URL 上。

**失败一定回退**：没配地址、连不上、超时、非 200、返回不是图片、图太大，
全部都回退成**文本**发送（命中敏感词时回退成打码后的文本），帮助功能不会因为渲染服务
挂掉而不可用，日志里会写 `帮助文档图片渲染失败，已回退为文本`。

配置键（`data/helpdoc/help_config.yaml`，管理界面里改）：

```yaml
imageRenderEnable: true
imageRenderMinLength: 1200        # 超过 1200 字转图片；0 = 不按长度触发
imageRenderMaskInImage: false     # true = 图片里也打码
imageRenderUrl: "http://127.0.0.1:3212/render"
imageRenderToken: "换成你自己的令牌"
imageRenderTimeoutSec: 15         # 0 视为 15
imageRenderWidth: 820             # 0 视为 820
```

**渲染后端**：`tools/helpdoc-render`（纯 Go、无浏览器、常驻内存十几 MB），
接口契约、编译与部署（systemd / docker compose）、字体安装都在
[`tools/helpdoc-render/README.md`](../tools/helpdoc-render/README.md)。后端挂了只是不发图，
不会影响海豹本体。

**不足 / 风险（务必读完）**：

1. **必须自部署一个服务**，多一个进程要维护（内存占用不大，但要有 systemd/compose 兜底重启）。
2. **每次渲染都有成本**：不做缓存（这是需求），长文档 + 频繁 `.help` 会吃 CPU；
   后端默认并发上限 2 就是为了限制峰值内存。
3. **体验退化**：图片不能复制、不能搜索、读屏软件读不了；长文档会被截断并在图末提示。
4. **合规风险**：把文本转成图片，本质上是**绕过平台的文本审核**。这通常**违反平台服务条款**，
   官方 QQ 也有图片 OCR 审核能力；一旦被判定为绕审，轻则限流、重则封禁机器人。
   请自行评估，我无法保证不被处罚。若目的只是避免**误伤**，更稳的做法是词表白名单 +
   降低等级 + 仅警告，而不是换图片。
5. 渲染后端能看到帮助正文（自部署可接受）；因此默认用 base64 内联、不走公网 URL。

## 三、回退到官方主线 / 旧版本

两个功能都**没有数据库变更**，也没有数据迁移：

| 内容 | 存放位置 | 旧版本会怎样 |
|---|---|---|
| `censorMaskEnable` / `censorMaskChar` | `serve.yaml` | 未知键被**忽略**（yaml 默认行为） |
| `imageRender*` 七个键 | `data/helpdoc/help_config.yaml` | 同上，忽略 |
| 渲染后端 | 独立进程 | 停掉即可，海豹不受影响（只是不再发图） |

所以回退仍然是「换个镜像 tag」级别；旧版本保存设置时可能把上面的键从文件里抹掉，
再切回来重新填一遍即可。完整清单见
[`docs/how-to-revert-to-upstream.md`](./how-to-revert-to-upstream.md) 的第二节。

## 四、自测清单

- [ ] 拦截词页打开「出站掩码」，往词表加一个词（如 `测试敏感词`），让骰子发一条含该词的
      自定义回复 → 群里应看到 `口口口口口`，日志里出现 `出站掩码（群...）：命中「测试敏感词」已替换`
- [ ] 同一条内容由**帮助文档**发出（把词写进某个词条）→ 应打码，且**不增加**该用户的违规计数
- [ ] 帮助文档图片化：填好后端地址 → `.help` 一个命中词条的正文 → 应收到图片
- [ ] 把 `imageRenderMinLength` 设成 100 → `.help` 一个长词条 → 应收到图片
- [ ] 停掉渲染后端 → 再 `.help` → 应收到**文本**（而不是报错或空回复）
- [ ] 换回旧镜像 → 一切照旧（上面的键被忽略）
